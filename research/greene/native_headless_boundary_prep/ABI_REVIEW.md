# Native dispatcher ABI review before deployment

The first CPU helper linked successfully but used default debug headers. It was never loaded or invoked against libsvulkan2. Link success is insufficient: installed ELF exports vk::defaultDispatchLoaderDynamic of size0x13d8 (5080 bytes); default headers add a debug DispatchLoaderBase and yield5096 bytes, shifting every pointer16 bytes. This would write pointers at incorrect native offsets.

Compiling with NDEBUG matches the observed native size and every initialized offset: getproc0x48, create0, extensions0x68, layers0x78, version0x448. Binary Instance prefix disassembly independently shows all five fields at these addresses. Native loader uses dlopen flags2 (RTLD_NOW|RTLD_LOCAL), .so then .so.1; installed DynamicLoader header agrees. Helper now refuses non-NDEBUG builds and statically asserts all six layout properties. CPU mock translation uses the same release-layout header while re-enabling assertions for its independent checks. Production translation owns no separate dispatcher storage; ELF undefined symbol points to the original native global.

This proves the reviewed prefix layout, not exact upstream binary revision or all SAPIEN C++ ABI types. Baseline debug-layout compile artifact and CPU results stay in evidence/headless-validation-v2 and are explicitly superseded for any production preparation. No GPU launch occurred. A fresh GPU registration must freeze release-layout source/object and the verified observer dependency closure, recheck all budgets and pauses, and run native L1/L2/L3 before release.
