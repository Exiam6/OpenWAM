# 录制/回放渲染分歧：在策略看来，等于换了个场景

日期：2026-10-03。状态：**已实测**（潜变量层面）。

## 0. 结论

同一个场景、物理状态复现到 1e-6，但重新渲染后的图像在策略的视觉编码器里**移动了约 30% 的潜变量范数**——这个距离**超过了数据集中最相似的两个不同场景之间的距离**（109.5%）。

图像层面的差异只有 **1.03 个 uint8 级**（每像素 0.4%）。

## 1. 背景：已确认的事实

`evaluate_policy.py` 在比较渲染前先断言物理状态：

```python
assert np.allclose(state, ref["state"], rtol=0, atol=1e-6), "Initial proprio mismatch"
assert np.allclose(got.p, pose["p"], ...) and np.allclose(got.q, pose["q"], ...), "Initial scene pose mismatch"
```

这两条在全部 135 个 cell 上都通过。**状态是复现的，分歧只在渲染。**

| | Shenlong（RTX PRO 6000 Blackwell） | Torch（L40S） |
| --- | --- | --- |
| 全部场景 MAE | **0.52 – 1.03** | **0.0604 – 0.337**（中位 0.1019） |
| `seed-1102008` | 1.0315（**被闸门拒**） | 0.3032（通过） |

两边用**完全相同的评测标志**（`eval_mode=True, is_test=True, render_freq=0, save_data=False`），所以分歧里存在**机器相关分量**，不是采集/评测配置差异。

Shenlong 侧跨 9 次独立运行的离散度是 **0.00**——确定性的，不是 GPU 抖动。

## 2. 这次要回答的问题

0.5–1.0 个 uint8 级的偏差，在策略实际使用的空间里是大是小？

**做法**：把参考 PNG 和评测时的实际渲染分别过策略的视觉编码器（`DinoV3VideoEncoder`，`batch_encode`），测量潜变量差异，并与**同一空间里的场景间距离**对照。

对照必须同空间同尺寸——第一版拿 15×20 的渲染潜变量去比 cache 里 24×20 的场景潜变量，那是两个空间，已废弃。

## 3. 结果

素材：`place_object_basket/seed-1102008`（被闸门拒的那个场景）的参考 PNG 与实际渲染；对照是另外 17 个录制场景的参考 PNG，同样过编码器。

| | 240×320（相机原始） | 384×320（训练网格） |
| --- | --- | --- |
| 潜变量维度 | 691,200 | 1,105,920 |
| 渲染扰动 \|dz\| | 239.10 | 315.26 |
| 占潜变量范数 | 28.76% | **29.98%** |
| 到最近的其他场景 | 461.81 | 584.23 |
| 到中位其他场景 | 670.07 | 826.35 |
| **最相似的同任务场景对** | 246.99 | 287.89 |
| 渲染 / 最近其他场景 | 51.8% | **54.0%** |
| 渲染 / 中位其他场景 | 35.7% | 38.2% |
| **渲染 / 最相似同任务场景对** | 96.8% | **109.5%** |

**结论对分辨率稳健**：两个尺寸下相对量几乎一致（28.76% vs 29.98%）。

`_preprocess_image` 不做任何缩放（只做 ImageNet 归一化），所以两个尺寸都是直接入编码器；真实服务路径里的缩放步骤本脚本未触及，两头都测正是为了确认结论不依赖它。

## 4. 这意味着什么

**策略在采集渲染上训练，在评测渲染上被评测**，而两者的差距在视觉潜变量空间里和"换一个场景"同量级。这是评测框架自己引入的分布偏移，而且因为没人记录 `initial_render_mae`，它是静默的。

它还重新定性了我们账本里的"9 个技术失败"：那不是一个坏场景，而是一个影响全部 135 个 cell 的系统性偏差的尾部，恰好有一个场景越过了 1.0 的闸门。Torch 的数据进一步说明，**被拒的是 Shenlong 的渲染路径，不是那个场景**——同一场景在 Torch 上是 0.3032，轻松通过。

## 5. 保留意见（重要）

- **这是潜变量层面的测量，不是动作层面。** 若扰动落在策略不敏感的方向上，可能不影响最终动作。本结果是强先验，不是闭环证据。
- 只测了**一个场景**（1102008）的渲染对，因为只有被拒的 cell 会保存 `initial-actual-*.png`。其他场景的实际渲染没有留存。
- 只测了 `head_camera`，且只用 `raw768_native` 这一个编码器。
- 场景间距离用的是 18 个录制场景的参考 PNG，不是完整分布。

## 6. 下一步

1. 让评测在**每个** cell 都保存实际渲染（现在只在越闸门时保存），这样能把上面的测量扩到全部 135 个 cell，而不是一个。
2. 动作层面的验证：同 checkpoint、同指令、同 proprio，两种渲染分别过完整服务路径，比对输出动作块。
3. 定位机器相关分量：Shenlong 是 Blackwell sm_120 + 驱动 580.95.05，Torch 是 L40S sm_89；嫌疑包括光追/降噪实现差异（`LD_LIBRARY_PATH` 里挂着 `sapien/oidn_library`，且 `downloads/` 里有 `oidn-2.3.3`）。
