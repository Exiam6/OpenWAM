# 录制/回放渲染分歧：在策略看来，等于换了个场景

日期：2026-10-03。状态：**已实测，n=60**（潜变量层面）。

## 0. 结论

同一个场景、物理状态复现到 1e-6，但重新渲染后的图像在策略的视觉编码器里**移动了约 30% 的潜变量范数**。

**全部 60 个场景无一例外**：每一个的渲染扰动都超过了数据集中最相似的两个同任务场景之间的距离（中位 **123.1%**，**60/60**）。

图像层面的差异中位只有 **0.566 个 uint8 级**（每像素 0.22%）。

附带发现：**闸门量错了东西**。闸门卡的是图像 MAE，但图像 MAE 与潜变量扰动不同向——`place_object_basket` 图像 MAE 最高（中位 0.7793）而潜变量扰动最低（288.5），`handover_block` 反之（0.5592 / 336.2）。被闸门拒掉的那个场景，恰好属于潜变量上受影响最小的任务。

## 1. 背景：已确认的事实

`evaluate_policy.py` 在比较渲染前先断言物理状态：

```python
assert np.allclose(state, ref["state"], rtol=0, atol=1e-6), "Initial proprio mismatch"
assert np.allclose(got.p, pose["p"], ...) and np.allclose(got.q, pose["q"], ...), "Initial scene pose mismatch"
```

这两条在全部 135 个 cell 上都通过。**状态是复现的，分歧只在渲染。**

| | Shenlong（RTX PRO 6000 Blackwell） | Torch（L40S） |
| --- | --- | --- |
| 全部场景 MAE | **0.52 – 1.03** | **0.0604 – 0.337**（中位 0.1019） |
| `seed-1102008` | 1.0315（**被闸门拒**） | 0.3032（通过） |

两边用**完全相同的评测标志**（`eval_mode=True, is_test=True, render_freq=0, save_data=False`），所以分歧里存在**机器相关分量**，不是采集/评测配置差异。

Shenlong 侧跨 9 次独立运行的离散度是 **0.00**——确定性的，不是 GPU 抖动。

## 2. 这次要回答的问题

0.5–1.0 个 uint8 级的偏差，在策略实际使用的空间里是大是小？

**做法**：把参考 PNG 和评测时的实际渲染分别过策略的视觉编码器（`DinoV3VideoEncoder`，`batch_encode`），测量潜变量差异，并与**同一空间里的场景间距离**对照。

对照必须同空间同尺寸——第一版拿 15×20 的渲染潜变量去比 cache 里 24×20 的场景潜变量，那是两个空间，已废弃。

## 3. 结果

素材：`place_object_basket/seed-1102008`（被闸门拒的那个场景）的参考 PNG 与实际渲染；对照是另外 17 个录制场景的参考 PNG，同样过编码器。

| | 240×320（相机原始） | 384×320（训练网格） |
| --- | --- | --- |
| 潜变量维度 | 691,200 | 1,105,920 |
| 渲染扰动 \|dz\| | 239.10 | 315.26 |
| 占潜变量范数 | 28.76% | **29.98%** |
| 到最近的其他场景 | 461.81 | 584.23 |
| 到中位其他场景 | 670.07 | 826.35 |
| **最相似的同任务场景对** | 246.99 | 287.89 |
| 渲染 / 最近其他场景 | 51.8% | **54.0%** |
| 渲染 / 中位其他场景 | 35.7% | 38.2% |
| **渲染 / 最相似同任务场景对** | 96.8% | **109.5%** |

**结论对分辨率稳健**：两个尺寸下相对量几乎一致（28.76% vs 29.98%）。

`_preprocess_image` 不做任何缩放（只做 ImageNet 归一化），所以两个尺寸都是直接入编码器；真实服务路径里的缩放步骤本脚本未触及，两头都测正是为了确认结论不依赖它。

## 4. 这意味着什么

**策略在采集渲染上训练，在评测渲染上被评测**，而两者的差距在视觉潜变量空间里和"换一个场景"同量级。这是评测框架自己引入的分布偏移，而且因为没人记录 `initial_render_mae`，它是静默的。

它还重新定性了我们账本里的"9 个技术失败"：那不是一个坏场景，而是一个影响全部 135 个 cell 的系统性偏差的尾部，恰好有一个场景越过了 1.0 的闸门。Torch 的数据进一步说明，**被拒的是 Shenlong 的渲染路径，不是那个场景**——同一场景在 Torch 上是 0.3032，轻松通过。

## 4b. 全 60 场景普查（n=60）

重新渲染全部 60 个录制场景的初始状态并与参考比对。不跑策略、不计分，所以 attempt-once 纪律不适用。**60/60 成功，零失败**，耗时 31.4 分钟。

### 图像层面

| | min | median | max |
| --- | --- | --- | --- |
| 三相机最大 MAE | **0.5116** | 0.5718 | 1.0315 |

| 任务 | n | 中位 | max |
| --- | --- | --- | --- |
| `adjust_bottle` | 20 | 0.5372 | 0.5669 |
| `handover_block` | 20 | 0.5718 | 0.6143 |
| `place_object_basket` | 20 | 0.7824 | **1.0315** |

**每一个场景的 MAE 都 ≥ 0.51。** 分歧是普遍的，不是离群值；1.0 的闸门恰好只抓住分布的尾巴那一个。

### 潜变量层面（`head_camera`，384×320）

| | min | median | max |
| --- | --- | --- | --- |
| 渲染扰动 \|dz\| | 259.16 | **315.22** | 390.79 |
| 同任务场景对（n=570） | **256.04** | 506.86 | 734.89 |
| 跨任务场景对（n=1200） | 770.33 | 912.84 | 982.33 |

中位渲染扰动占潜变量范数 **29.97%**，与单场景测得的 29.98% 一致。

| 比值 | 值 |
| --- | --- |
| 中位渲染 / **最小**同任务场景对 | **123.1%** |
| 中位渲染 / 中位同任务场景对 | 62.2% |
| **渲染扰动超过最小同任务场景对的场景数** | **60 / 60** |

单场景测得的 109.5% 不是侥幸——60 个场景的中位是 123.1%，且**无一例外**全部超过。

### 图像 MAE 不预测潜变量扰动

| 任务 | 中位图像 MAE | 中位潜变量 \|dz\| |
| --- | --- | --- |
| `adjust_bottle` | 0.5371 | 316.5 |
| `handover_block` | 0.5592 | **336.2** |
| `place_object_basket` | **0.7793** | **288.5** |

图像 MAE 最高的任务潜变量扰动最低，反之亦然。**闸门卡的是图像 MAE，而策略实际受影响的是潜变量**，两者不同向——被拒的 `seed-1102008` 恰好属于潜变量上受影响最小的那个任务。这说明现在的闸门不仅阈值定得巧合，量的维度也不对。

## 5. 保留意见（重要）

- **这是潜变量层面的测量，不是动作层面。** 若扰动落在策略不敏感的方向上，可能不影响最终动作。本结果是强先验，不是闭环证据。
- 潜变量普查覆盖全部 60 个场景，但只测了 `head_camera`，且只用 `raw768_native` 这一个编码器。
- 场景间距离用的是这 60 个录制场景，是本研究的完整集合，但不是 RoboTwin 的完整分布。
- 普查的重渲染与评测时的渲染是两次独立运行；二者一致（1102008 两边都是 1.0315），但严格说普查测的是"再渲染一次"而非"评测当时那一次"。
